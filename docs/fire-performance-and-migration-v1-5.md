# Fire workload and migration heading

Implemented:

- Migration silhouettes and their V formation use the explicit world view matrix exactly once, and a horizontal local frame aligned with their X/Z trajectory. Both wings flap together rather than banking the entire bird. A first migration packet on a new world is retained.
- Near fire bodies use the animated vanilla fire atlas in one client mesh, with stable sub-block ignition anchors and interpolated sizes. No ordinary per-front flame/smoke/bridge particle packets are emitted by EnhancedFireVisuals. Large smoke volumes remain for the horizon.
- A maximum of 128 nearby flame representatives is sent per viewer every ten ticks, within 96 blocks and the same dimension. Mature adjacent fires coalesce into two-block cells; the closest representatives are preferred. This is visual LOD, not a terrain edit. Additional large fires are represented by the smoke volumes. Removal is validated on client ticks; frames expire after 35 ticks without updates or on world change.
- Custom fire work rotates up to 64 tracked fires per tick (rather than 256 in one four-tick burst). Growth, wetness and cooldowns use elapsed simulation time. Cluster density/primary selection shares one 26-neighbor scan cached for 20 ticks, instead of repeating scans for growth, smoke and sound.
- Extra ember searches have a hard global limit of 256 probes per four ticks, including failed attempts, and eight successful custom ignitions per four ticks. Existing 24-block custom-source reach and doFireTick rules remain.
- Vanilla scheduled fire ticks, including density checks, are limited to 64 per dimension per tick; overload is rescheduled 20–39 ticks later, preserving extinction/aging/spread processing instead of losing ticks. Under heavy overload this intentionally slows native propagation. Crowding uses cached 8x4x8 section samples, without requesting unfinished chunks. Crowded ordinary cells thin at 32 fires; dimension-specific infiniburn support remains exempt. doFireTick=false never triggers density thinning.
- At most two new volume-smoke parcels and eight crackle sounds are emitted globally per second; smoke creation also shares a regional cooldown. At most twelve extended heat-box entity queries run per tick; vanilla collision fire damage remains active.
- Custom neighbor and ignition inspection reads only immediately available server chunks, and ignores absent chunks. The native scheduled fire algorithm remains vanilla after budget admission; its own vanilla chunk rules are preserved.

Validation: standalone contracts stress failed-search budgets and migration heading. Dedicated-server tests cover disabled fire ticks, crowded/permanent source behavior, maximum flame-frame codec round trips and malformed frames. Build, normal seed-42 server boot and client registration/resources run in CI. Manual gameplay still needs to verify GPU composition, camera turns, migration pitch and the fire/smoke appearance at different distances. No numerical FPS improvement is asserted. Client and server must use the same build because the visual frame payload is new.
